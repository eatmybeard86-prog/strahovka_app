# Облік роти

Веб-застосунок для обліку надходжень і витрат роти за категоріями потреб (пальне, харчування, ремонт техніки, дрони тощо). Вхід лише за логіном і паролем, у кожного користувача свої права.

## Що вміє

- **Користувачі з ролями.**
  - *Лише перегляд*: бачить звіт і операції, нічого не змінює (наприклад, командир).
  - *Редактор*: вносить, змінює й видаляє операції. Адміністратор може обмежити його окремими категоріями (наприклад, старшина працює лише з «Харчуванням»).
  - *Адміністратор*: усе, плюс категорії, користувачі й журнал дій.
- **Журнал дій.** Хто й коли входив, вносив, змінював чи видаляв операції (зі старим і новим значенням), змінював категорії та користувачів. У списку операцій видно, хто вніс кожну.
- **Операції.** Надходження та витрати з датою, сумою, категорією, контрагентом («від кого» / «кому») і описом.
- **Категорії.** Додавання, перейменування, архівування (категорія з операціями не видаляється, лише ховається з вибору для нових записів).
- **Звіт.** За будь-який період по кожній категорії: залишок на початок, надійшло, витрачено, залишок на кінець, плюс підсумок.
- **Фільтри та експорт.** Пошук операцій за періодом, типом, категорією й текстом; вивантаження в CSV, який відкривається в Excel.
- **Безпека.** Паролі зберігаються як хеші scrypt. Після 10 невдалих спроб вхід з тієї ж адреси блокується на 15 хвилин. Вимкнення користувача або зміна його пароля одразу завершує його сесії. Кожен може змінити власний пароль, натиснувши своє ім'я вгорі.

## Безкоштовне розгортання: Render + Neon

Застосунок працює на безкоштовному плані Render, а дані зберігаються в безкоштовній базі PostgreSQL від [Neon](https://neon.tech) (0,5 ГБ, без строку дії). Так записи не зникають, хоча безкоштовний сервіс Render не має постійного диска.

1. Зареєструйтеся на [neon.tech](https://neon.tech), створіть проєкт у регіоні **Frankfurt** і скопіюйте **Connection string** (`postgresql://…neon.tech/neondb?sslmode=require`).
2. На [dashboard.render.com](https://dashboard.render.com) натисніть **New → Blueprint** і виберіть цей репозиторій.
3. Введіть `DATABASE_URL` (рядок з Neon) і `ADMIN_PASSWORD` (пароль першого адміністратора з логіном `admin`).
4. Відкрийте адресу `https://oblik-roty….onrender.com`, увійдіть як `admin`, змініть пароль і створіть користувачів на вкладці «Користувачі».

Безкоштовний сервіс Render «засинає» після 15 хвилин без відвідувань, тож перше відкриття після перерви займає до хвилини. Дані при цьому не втрачаються.

## Локальний запуск

Потрібен Node.js 22.5 або новіший. Без `DATABASE_URL` дані зберігаються у вбудованому SQLite у файлі `data/oblik.db`.

```bash
npm install
ADMIN_PASSWORD='надійний-пароль' npm start
# відкрийте http://localhost:3000 і увійдіть як admin
```

### Через Docker

```bash
echo "ADMIN_PASSWORD=надійний-пароль" > .env
docker compose up -d --build
```

Дані зберігаються в томі `oblik-data` (файл `/data/oblik.db`).

## Налаштування

| Змінна | Призначення | За замовчуванням |
|---|---|---|
| `ADMIN_PASSWORD` | Пароль першого адміністратора; потрібен лише поки в базі немає користувачів | — |
| `ADMIN_LOGIN` | Логін першого адміністратора | `admin` |
| `PORT` | Порт сервера | `3000` |
| `DATABASE_URL` | Рядок підключення до PostgreSQL (Neon тощо). Якщо не задано, використовується SQLite | — |
| `DATA_DIR` | Тека з базою SQLite | `./data` |
| `SESSION_DAYS` | Скільки днів діє вхід | `7` |
| `COOKIE_SECURE` | `1`, якщо сайт працює через HTTPS | вимкнено |
| `TRUST_PROXY` | `1`, якщо перед застосунком стоїть проксі (nginx, Caddy, Render) | вимкнено |

## Резервні копії

Neon зберігає історію змін бази й дозволяє відновити її на момент у минулому (на безкоштовному плані за останню добу). Додатково варто періодично вивантажувати CSV з вкладки «Операції». Для SQLite достатньо копіювати файл `oblik.db`.

## Тести

```bash
npm test
# перевірка на PostgreSQL (порожня база):

```
