# Скриня

Скриня — веб-застосунок для обліку надходжень і витрат роти за категоріями потреб (пальне, харчування, ремонт техніки, дрони тощо). Вхід лише за логіном і паролем, у кожного користувача свої права.

## Що вміє

- **Користувачі з ролями.**
  - *Лише перегляд*: бачить звіт і операції, нічого не змінює (наприклад, командир).
  - *Редактор*: вносить, змінює й видаляє операції. Адміністратор може обмежити його окремими категоріями (наприклад, старшина працює лише з «Харчуванням»).
  - *Адміністратор*: усе, плюс категорії, користувачі й журнал дій.
- **Журнал дій.** Хто й коли входив, вносив, змінював чи видаляв операції (зі старим і новим значенням), змінював категорії та користувачів. У списку операцій видно, хто вніс кожну.
- **Рахунки: де лежать кошти.** Довідник рахунків і місць зберігання (наприклад, «Каса старшини», «Картка ст. сержанта Петренка»), кожен з позначкою готівка чи безготівка. В операції вказується, на який рахунок надійшли кошти чи з якого витрачено, а звіт показує залишок по кожному рахунку і разом готівкою та безготівково. Користувачі з роллю «лише перегляд» бачать лише, готівка це чи безготівка: назви рахунків (у кого і де лежать кошти) та опис операцій від них приховані, зокрема в API та CSV.
- **Особисте: борги та витрати.** Окрема вкладка для особистих боргів («хто винен», «кому», сума, примітка) і особистих витрат людей. Ці записи не впливають на звіт і залишки роти. Видно, хто кому скільки винен (зустрічні борги згортаються), сальдо кожної людини, а борг можна позначити поверненим. Адміністратор бачить розділ завжди, іншим користувачам доступ надає або закриває адміністратор у вкладці «Користувачі» (за замовчуванням закрито). Хто має доступ: вносити й змінювати — редактор і адміністратор; глядач лише переглядає і не бачить приміток.
- **Операції.** Надходження та витрати з датою, сумою, категорією, контрагентом («від кого» / «кому») і описом.
- **Категорії.** Додавання, перейменування, архівування (категорія з операціями не видаляється, лише ховається з вибору для нових записів).
- **Звіт.** За будь-який період по кожній категорії: залишок на початок, надійшло, витрачено, залишок на кінець, плюс підсумок.
- **Фото чеків.** До витрати можна додати до 5 фото чеків (камера або галерея). Сторінка сама стискає кожне фото ще на телефоні (до 1600 px, JPEG, зазвичай 100–250 КБ), а сервер зберігає його в базі даних, тож фото переживають перезапуск безкоштовного сервера. Переглядають усі ролі (значок 🧾 у списку операцій), додають і видаляють адміністратор і редактор із доступом до категорії; у журналі дій видно, хто додав чи видалив фото. Після входу з SOS-паролем справжніх фото не видно.
- **Фільтри та експорт.** Пошук операцій за періодом, типом, категорією й текстом; вивантаження в CSV, який відкривається в Excel.
- **SOS-пароль.** Адміністратор може задати у вкладці «Користувачі» окремий SOS-пароль (зберігається як хеш, має відрізнятися від справжніх паролів адміністраторів). Якщо людину змушують увійти, вона вводить свій логін адміністратора і SOS-пароль: відкривається звичайний на вигляд застосунок з тим самим ім'ям, але з вигаданими операціями в окремій базі в пам'яті. Справжніх даних там не видно, а все, що змінять у такій сесії, на них не впливає (і зникає після перезапуску сервера). Розділу SOS-пароля в такій сесії немає. У справжньому журналі дій з'являється запис «Вхід із SOS-паролем» з адресою. Вимкнення SOS-пароля завершує всі такі сесії.
- **Безпека.** Паролі зберігаються як хеші scrypt. Після 10 невдалих спроб вхід з тієї ж адреси блокується на 15 хвилин. Вимкнення користувача або зміна його пароля одразу завершує його сесії. Кожен може змінити власний пароль, натиснувши своє ім'я вгорі.

## Безкоштовне розгортання: Render + Neon

Застосунок працює на безкоштовному плані Render, а дані зберігаються в безкоштовній базі PostgreSQL від [Neon](https://neon.tech) (0,5 ГБ, без строку дії). Так записи не зникають, хоча безкоштовний сервіс Render не має постійного диска.

1. Зареєструйтеся на [neon.tech](https://neon.tech), створіть проєкт у регіоні **Frankfurt** і скопіюйте **Connection string** (`postgresql://…neon.tech/neondb?sslmode=require`).
2. На [dashboard.render.com](https://dashboard.render.com) натисніть **New → Blueprint** і виберіть цей репозиторій.
3. Введіть `DATABASE_URL` (рядок з Neon) і `ADMIN_PASSWORD` (пароль першого адміністратора з логіном `admin`).
4. Відкрийте адресу `https://oblik-roty….onrender.com`, увійдіть як `admin`, змініть пароль і створіть користувачів на вкладці «Користувачі».

Безкоштовний сервіс Render «засинає» після 15 хвилин без відвідувань, і перше відкриття після цього займає до хвилини. Щоб цього не було вдень:

- застосунок сам звертається до своєї адреси кожні 10 хвилин у години `KEEPALIVE_HOURS` (за замовчуванням `7-23` за київським часом), а вночі засинає;
- розклад GitHub Actions (`.github/workflows/keepalive.yml`) будить його зранку й підстраховує вдень.

Так сервіс працює близько 500 годин на місяць із 750 безкоштовних годин Render на весь акаунт. Якщо в тому ж акаунті Render є інші безкоштовні сервіси, вони ділять цей ліміт. Цілодобовий режим (`KEEPALIVE_HOURS=0-24`) забирає близько 744 годин.

## Локальний запуск

Потрібен Node.js 22.5 або новіший. Без `DATABASE_URL` дані зберігаються у вбудованому SQLite у файлі `data/oblik.db`.

```bash
npm install
ADMIN_PASSWORD='надійний-пароль' npm start
# відкрийте http://localhost:3000 і увійдіть як admin
```

### Через Docker

```bash
echo "ADMIN_PASSWORD=надійний-пароль" > .env
docker compose up -d --build
```

Дані зберігаються в томі `oblik-data` (файл `/data/oblik.db`).

## Налаштування

| Змінна | Призначення | За замовчуванням |
|---|---|---|
| `ADMIN_PASSWORD` | Пароль першого адміністратора; потрібен лише поки в базі немає користувачів | — |
| `ADMIN_LOGIN` | Логін першого адміністратора | `admin` |
| `PORT` | Порт сервера | `3000` |
| `DATABASE_URL` | Рядок підключення до PostgreSQL (Neon тощо). Якщо не задано, використовується SQLite | — |
| `DATA_DIR` | Тека з базою SQLite | `./data` |
| `IDLE_MINUTES` | Через скільки хвилин без дій автоматично виходить (сайт і застосунок Android) | `5` |
| `COOKIE_SECURE` | `1`, якщо сайт працює через HTTPS | вимкнено |
| `KEEPALIVE_HOURS` | Години (за Києвом), коли сервіс не дає собі заснути: `7-23`, `0-24` або `off` | `7-23` |
| `KEEPALIVE_URL` | Публічна адреса для самопінгу (на Render береться автоматично з `RENDER_EXTERNAL_URL`) | — |
| `TRUST_PROXY` | `1`, якщо перед застосунком стоїть проксі (nginx, Caddy, Render) | вимкнено |

## Резервні копії

Neon зберігає недавню історію змін бази й дозволяє відновити її на момент у минулому (на безкоштовному плані вікно відновлення коротке). Додатково варто періодично вивантажувати CSV з вкладки «Операції». Для SQLite достатньо копіювати файл `oblik.db`.

## Тести

```bash
npm test
# перевірка на PostgreSQL (порожня база):
TEST_DATABASE_URL=postgres://… npm test
```
